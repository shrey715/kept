How we decide

Four rules picked every technology before we wrote the solution.

01

Evidence before features

A change ships only if it beats what's live by more than the noise, on data it never saw.

02

Nothing leaves the machine

Every model runs locally: customer words never cross a network, no keys, no quota, no per-call cost.

03

Models propose, people release

No model sends anything. Rules run before scoring and again at release; Red needs two people.

04

Every number reproducible

Each claim names its report and the command that rebuilds it, down to this deck's numbers.

Backend architecture · the two paths

A nightly batch prepares; a live request decides.

Nightly · kept nightly

  1. Land 31 tables, dbt build silver and gold, data contract gate
  2. Identity: exact links, then Splink; doubtful pairs to a steward
  3. Text: redact, extract with quotes (local Qwen3.8-27B)
  4. Features as of 06:00 UTC into Feast; drift (PSI) and fairness checks
  5. Score every open case: {{KopenCases}} cards in about 85 s

Live · one case, one person

  1. Agent opens a case: the card is re-scored on fresh features
  2. A new note is redacted and read in seconds; hardship can flip the card
  3. The reviewer approves: the gate re-runs every rule (consent, hours, caps)
  4. Red needs a specialist and a second person; approvals expire in 4 h
  5. Every step is appended to the hash chain

Kept · extraction_gate.md · src/kept/common/llm.py8
Why this model: we measured, we did not assume. The 12B model kept missing conventions; tracing it showed Ollama silently ran a 4k window under a 9k prompt. We moved to llama.cpp with an explicit window, then picked the newest strong open model that fits 16 GB, Qwen3.8-27B at 3-bit, and re-ran every benchmark. Bigger Gemma 4 and hosted APIs were rejected on speed, privacy and a quota that broke a run. Schema-constrained decoding is what makes any local model reliable: malformed replies went to zero.

Why a graph and not one big prompt: each step is testable and traced. When the model slips (drops "calls", writes CURRENT_DATE, computes its own dates, names a column loosely) a deterministic check fixes it or sends it back with the reason, like a linter.
