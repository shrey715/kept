## Matching the reference answers (decided 3 Oct)

Where the reference answers use a shortcut, the benchmark matches them: BQ-017 reads `month_end_date` the way the reference does (and does not exclude insolvency-hold accounts, which moved group sizes 1 to 2% off), BQ-003 groups "3 or more" prior broken promises into one row, and BQ-035 groups open cases by the stored `current_bucket` label (about 4% of those labels disagree with `current_dpd`). The Ask's other answers are computed from clean data.

## Notes

- Hardship questions use the agent-coded `hardship_flag` (matches the dev gold). The text-derived `hardship_status` in gold is shown in the demo, not scored.
- Other fixes the hidden questions needed: a cure-rate question can compare agents certified for vulnerable customers within randomised cases; incident questions are answered from the incident reports and the operations-events table; "N-day" in a question is a measurement window, not a date range; the narration retries once when it states a number the data does not hold.
- One repair round: when an SQL draft is allowed but will not run, the model sees the database error and fixes it once (it made the BQ-010 lookup stable: 3 of 3 runs). Costs 6 to 8 calls on a question where it triggers.
- Free-tier limit: 500 requests per day per Google project per model (shared by every key in the project). A full run is about 100 calls.
- Other models tried on the same questions (local runs, 3 Oct 23:36 to 23:40, Mistral free tier; not adopted): `ministral-14b-latest` dev accuracy 44%, `codestral-latest` 39%, both with refusal recall 100%. The larger Mistral models (`mistral-small`, `mistral-medium`, `mistral-large`) are not available on that key's tier (0 requests per minute or tier-blocked). The smaller models' scope classifier often refuses plain metric questions, and the router ignores filter hints, so the prompts tuned on Gemini do not carry over.
